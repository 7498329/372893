# 兰州牛肉面 · 一碗面的十二种活法

一支 8 屏的线性叙事 H5。淡水墨国风、米黄宣纸底、浅青墨色，全程以用户提供的原画素材为唯一图像来源。

## 发布（线上版）

成品目录是 `dist/`，只含 `index.html` + `assets/`（约 1.9 MB），无外部依赖、无构建步骤：

```bash
python publish.py     # 把 index.html / README.md / assets 同步进 dist
```

线上地址：**https://7498329.github.io/372893/lanzhou-noodle/**（GitHub Pages，仓库 `7498329/372893` 的 `lanzhou-noodle/` 目录；`deploy_via_api.py` 用 GitHub REST API 上传，绕开本机 git 的代理与凭据问题）。

改完源文件后重跑一次 `publish.py`，再发布 `dist/` 即可。原图、调试脚本、截图都留在上级目录，不会上传。

## 运行

直接双击 `index.html`，或用任意静态服务器打开（推荐，避免个别浏览器对本地 webp 的限制）：

```bash
python -m http.server 8899
# 打开 http://127.0.0.1:8899/index.html
```

无外部依赖，无需构建。

## 设备适配

**一块画布**：全站只有一个 750×1334 的竖版舞台（`#stageP`），P1–P8 都在里面按竖版排布。横版不再单独存在——第二到第七页（面牌、拖拽、时间轴）是把原来的横版构图**顺时针旋转 90°** 重排成竖版的：标题在上、主体在中、操作在下，文字一律正立。

- **手机（短边 ≤ 600）**：铺满。按 cover 放大，`750` 那条边撑满屏幕宽，多出来的部分左右各裁一点纸边（裁切量写进 CSS 变量 `--crop`，最多 82 逻辑像素）；所有版式都排在 600 的安全宽内，标题、木牌、碗、食材、时间轴节点一个都不会被切。
- **P1 / P8**：这两页是整幅海报（不是版式），放大裁边会把「兰州牛肉面」的标题切掉——所以整页按可视宽度回缩（`--safe`），四周露一点纸底，海报一字不缺。
- **平板 / 桌面**：屏幕够大，等比缩放整块放下（`contain`），居中显示成一张竖的长卷，两侧是纸纹底色。
- **视口变化**（地址栏收放、横竖屏切换、拖窗口）统一走 `refit()`，时间轴的位移跟着归一化，不会翻屏错位。

## 真机可读性与触控目标

这块最大的坑是：**750 宽的画布在 390 手机上只有 0.633 的缩放**。写 15px 的字，真机量出来是 9.5px；写 40px 高的按钮，真机是 25px。所以本项目所有字号与控件尺寸都按「实际尺寸」反推，而不是按设计稿的直觉。

- **正文**：故事面板正文 22px（实际 ≈14px）、标题 33px（≈21px）、年份与辅助行 19–20px（≈12–13px）。
- **木牌背面**：18px / 行高 1.4，每列 7 字、3–4 列，列宽由字号算出，不依赖任何裁剪行为；翻开时整张牌放大到 1.55（实际 ≈18px）。
- **触控目标 ≥ 38×38 实际像素**：`fitStages()` 会按当前 `k` 把 38px 反算成逻辑值写进 `--tap`（`38 / k`），控件用 `max(设计值, var(--tap))` 取大者——375×667 的老 SE（k=0.5）自动放大到 76 逻辑，平板则保持设计值不无谓膨胀。
  - 时间节点：`max(72px, --tap)`
  - 翻页按钮：`min-height:max(70px, --tap)`
  - 面板关闭按钮：视觉 `max(46px, --tap - 20px)`，再用 `::before{inset:-14px}` 把热区外扩到 38px 以上
- 自检里 `touchTargets` 用 `getBoundingClientRect()` 直接量**真实渲染尺寸**判定（这个值已经是缩放后的视口像素，不能再乘 `k`——早先乘错一次，导致 27px 的按钮被判定为合格）。

## 键盘与焦点

- 木牌、时间节点、面板关闭键都是原生 `<button>`，并带 `aria-label`（如「毛细，寓意细如发丝，轻触翻看」），Tab 可达、Enter / Space 可触发。
- **未激活的页面用 `inert` 移出焦点树**：`.page` 只做 `opacity:0`，视觉上没了但按钮仍在 Tab 序列里，键盘用户会一路撞进看不见的控件。`go()` / `jump()` / 首屏各调一次 `syncInert()`，同时补 `aria-hidden` 给读屏。
- 键盘操作：`←/→/↑/↓/PgUp/PgDn` 翻屏与翻时间轴，`Esc` 收起翻牌模态与故事面板。

| P2 | 面型翻牌 壹：毛细 / 细 / 三细 / 二细 / 二柱子 / 韭叶 | 竖版 3×2 木牌网格 |
| P3 | 面型翻牌 贰：薄宽 / 宽 / 大宽 / 荞麦棱 / 空心面 / 五道丝面 | 竖版 3×2 木牌网格 |
| P4 | 拖拽成面：牛肉片 · 白萝卜 · 青蒜苗 · 鲜面条 四类入碗，吸附成面 | 大碗居中偏上 + 食材一排在下 |
| P5–P7 | 历史时间轴：一条弯曲面条自上而下串起 5 个节点，上下滑动浏览 | 纵向 750×4002，三屏吸附 |

## 交互细节

**翻牌（P2/P3）**
- 每张木牌点击触发绕 Y 轴翻转，正面→背面 180°，再次点击继续同向旋转到 360° 回到正面。
- 背面为竖排短文（取自 `面型` 文档，掐成两句、各二十余字）。
- 翻开的牌会被「拿」到画面中心放大 1.55 倍——竖版里木牌只有 180 逻辑宽，不放大背面小字在手机上读不清。
- 放大即进入**模态阅读**：其余牌压暗、去色、虚化并暂时不可点，底部主按钮从「下一屏」换成「收起」，点遮罩空白、点「收起」或按 Esc 都能退出；退出时长卷回到网格原位。
- 已经翻开但收回网格的牌，再点一下是「重新拿起来看」，不是翻回正面——否则读第二遍还得先翻回去。
- 位移与缩放写在 `.card` 自身（`--fx/--fy`），不是写在里面的子元素上：只动子元素的话，可见位置与可点位置会错开一个身位，看着在中间、点它却没反应。
- 两页数据完全独立：`flipCount = {2:0, 3:0}`，各自计数、各自焦点，互不影响。

**拖拽（P4）**
- 指针事件实现，按住即拿起（放大 1.04、投影加深），松手判定。
- 落点用逻辑坐标计算（`left/top + 位移 + 半宽高`），不依赖 `getBoundingClientRect()`，避免 CSS 过渡期间测到中间值。
- **位置自锁**：每次按下时先把当前位置"焊"到 `left/top` 上并清掉残留 `transform`，反复拖拽不会累积漂移；`pointerup` 同时挂在元素与 `window` 上，指针捕获失效也能正常收尾。
- 落入碗口椭圆（rx 237 / ry 197，含 10px 容差）自动吸附到预设槽位，并伴一圈白色涟漪。
- 四类全部入碗 → 0.2s 后成品碗淡入（1.3s）+ 白色热气升腾（5 缕，3.8s 循环）+ 碗旁弹出「你的专属面做好了」。
- 拖到碗外自动滑回原位，不误吸附。
- 白萝卜与白瓷碗同色，落碗后额外补一层贴身暖影 + 接触影 + 碗内极淡暗角，保证浅色料始终看得见（不修改素材本身）。
- 复位用 class 而非 inline 样式，`placedSet` 一并清空——从 P8 点「再拉一碗」重玩时不会误判"已满碗"。

**时间轴（P5–P7）**
- 主线就是用户提供的「历史脉络面条」原图：把面条按列重映射到一条设计好的正弦曲线上（`build2.py`），再把整条曲线顺时针旋转 90°（`build_v.js`）得到竖版长卷 `noodle_ribbon_v.webp`（370×3986），既保留原画笔触与厚度，又能自由控制蜿蜒形状。
- 5 个节点刻意落在波峰/波谷，使弹窗上下都有整块留白，绝不压住面条。
- 点击节点：该节点所在面段（上一节点与下一节点中点之间）整段染成辣椒红——用 SVG `mask` + `feColorMatrix` 只显影这一段，**保留面条本身的高光与肌理**，不是盖一条色块。
- 故事面板固定在屏幕下半部（宽度按 600 安全宽收），面板右上角有 `×` 可收起；面板展开时不显示「收尾」按钮，避免互相压住。
- 打开某个节点时，长卷会把这个节点顶到面板上方（y≈400）再弹故事，绝不出现「故事框盖住自己」。
- 长卷末尾留了 620px 的空白纸张（`TL_TAIL`）：最后一个节点在卷子最末端，不留这一截就永远滚不到面板上方。收起故事后长卷会自动回到三屏吸附位置（`snapBack()`），不会停在半途。
- 手指上下拖拽/甩动翻屏（3 屏，`translateY` + 松手吸附），滚到第 3 屏且面板收起后才出现「收尾」按钮。

**全局**
- 页面切换 0.72s 缓淡入；按钮按下 `scale(.94~.95)` 回弹。
- 时间轴竖向滑动（手指上下拖，桌面滚轮/↓↑ 也可），三屏吸附。
- 不再有任何「请把手机横过来」的提示、不申请全屏、不强锁方向——因为 P2–P7 本身就是竖版构图。
- 支持 `prefers-reduced-motion`。
**封面「那碗面颠三下」（P1）**
- 同一张海报叠了两层：底层完整静止，上层用 `clip-path: inset(27.7% 0 0 0)` 只留"碗与面"那半幅，接缝落在副标题下方的纯纸面（取的是原图 524/1920 行，全行无内容，肉眼无缝）。
- 入场 0.8s 淡入放大照旧由底层完成；上层在 0.86s 后淡入（与底层像素完全重合，看不出切换），1.1s 起连颠三下：−18px → 落地 → −9px → 落地 → −4px → 停。
- 只有纯位移、没有缩放：海报里的黄底按钮与 HTML 的「开始制作」按钮必须严丝合缝，任何缩放都会让两者错开一两像素。按钮用同一组关键帧、同一时长与缓动同步跳。
- 动画结束自动摘掉（`animationend` → `.hopDone`），否则 `animation-fill-mode: both` 会一直压住按钮的 `:active` 回弹。重回封面时会清掉标记，动画可以再演一次。

## 「页面打开后点不动」的成因与修复

早期版本里两块舞台（`#stageP` 750×1334 与 `#stageL` 1334×750）都绝对定位在视口正中、`z-index` 相同。`#stageL` 在 DOM 里靠后，即使 `opacity:0` 也照常参与命中测试，于是在竖屏页（P1/P8）它像一块透明玻璃盖住了整屏，把「开始制作 / 再拉一碗」全挡住了。现在只剩一块舞台，这个成因已从结构上消失，但两道保险仍然保留：

- `.stage{pointer-events:none}`、`.stage.live{pointer-events:auto}`：只有当前启用的舞台接收点击。
- `#veil.gone{pointer-events:none}`，并给遮罩加 `animation:veilAuto 3.4s forwards` 兜底：脚本没跑起来也会自己消失，不会永远挡在门口。
- `revealCover()` 里给 `.on` 加了 `setTimeout(…,120)` 双保险：后台标签页或被隐藏的 iframe 中 `requestAnimationFrame` 会挂起，页面可能停在「透明但存在」的状态，同样点不动。
- 回归验证：`?hit=1` 在各档尺寸下 P1–P8 全部 `hit=OK`；`?click=1` 各档尺寸均 `click=hit page=2 OK`。
